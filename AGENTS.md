# Anthology agent guide

Anthology is a self-hosted SvelteKit app that merges the libraries of several media servers (Plex, Jellyfin, later Navidrome, Kodi and ROM folders) into one searchable catalogue. It indexes metadata only. Playback happens on the source server through deep links. [PROJECT.md](PROJECT.md) is the product plan and milestone list.

## Layout

- `src/lib/server/adapters/`: one file per source type, each implementing `SourceAdapter` from `types.ts`. Register new adapters in `adapters/index.ts`. Core code must not know about specific sources.
- `src/lib/server/adapters/collection.ts`: the digital collection source. Its title list is stored in `collection_lists`, not in the encrypted credentials, and its items have an empty `link_url`.
- `src/lib/server/sync.ts`: full sync of one source. `WorkIndex` loads works once and matches in memory (override, external IDs, title + year, then a unique title when a year is missing). All writes go out through `writeBatch`, because a query per item is too slow against a remote database.
- `src/lib/server/matcher.ts`: pure title normalization and ID helpers.
- `src/lib/server/db.ts`: libSQL client (Turso on Vercel, a local SQLite file elsewhere), schema with FTS5 search, query helpers and database-backed locks. Every call is async. Do not rely on foreign key cascades: remote connections may not enforce them, so deletes are explicit (see `ORPHAN_CLEANUP`).
- `src/lib/server/streaming.ts`: subscription availability from TMDB watch providers (data from JustWatch). Not a source: it enriches existing works by TMDB ID. Keep the JustWatch and TMDB attribution visible wherever this data is shown.
- `src/lib/server/posters.ts`: fetches artwork through the adapter and passes on images only. Nothing is cached on the server.
- `src/lib/server/jobs.ts`: sync and availability runs guarded by database locks, plus `runScheduledJobs`, used by `/api/cron` on Vercel and by an in-process timer elsewhere.
- `src/lib/server/auth.ts`, `crypto.ts`: admin password, sessions, credential encryption.
- `src/routes/`: pages and form actions. `hooks.server.ts` enforces login on every route except `/login` and `/setup`.
- `src/lib/icons.ts` is generated by `npm run icons` from `scripts/generate-icons.mjs`. Add icon names there and regenerate. Do not edit the output.
- `tests/`: Vitest unit tests. Use the mock adapter and `openDb(':memory:')` instead of real servers.

## Project rules

- SvelteKit 3 here uses `#lib/...` package imports with explicit `.ts` extensions (for example `#lib/types.ts`), not `$lib`.
- Svelte 5 runes only.
- Use synthetic titles, IDs, hosts and passwords in tests, fixtures and screenshots. The mock datasets are invented on purpose.
- Never log or return source tokens. Error messages from adapters must not include URLs with credentials.
- Keep the app usable offline: no runtime calls to CDNs or the Iconify API.

## Stack

- SvelteKit (Svelte 5 runes) + TypeScript, Vite, adapter-node
- Tailwind CSS v4
- libSQL (`@libsql/client`): Turso on Vercel, a local SQLite file for development and Docker
- Deployed on Vercel (`@sveltejs/adapter-vercel` when `VERCEL` is set, `adapter-node` otherwise)
- Iconify (`@iconify/svelte`) with icons bundled offline
- Vitest for unit tests
- Prettier (tabs, single quotes, 120 character width)

| Task             | Command          |
| ---------------- | ---------------- |
| Dev server       | `npm run dev`    |
| Type check       | `npm run check`  |
| Lint (Prettier)  | `npm run lint`   |
| Format           | `npm run format` |
| Unit tests       | `npm test`       |
| Production build | `npm run build`  |

Serverless rules: no state in module memory that must survive between requests (use the database), no writes to the filesystem, and long jobs must respect a deadline.

Shared browser code goes in `src/lib/`, server-only code in `src/lib/server/`. Never import server code into browser code. Keep pure logic (parsing, matching, validation) separate from I/O so it can be tested in Node.

## Commits and attribution

- Use Conventional Commits: `type(optional-scope): imperative description`, with types `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`. Add `!` for breaking changes.
- One-line commit messages, no body or footer. Small, focused commits.
- No `Co-Authored-By:` trailers or "Generated with" lines in commits or PR bodies.
- Open pull requests from a branch. Run `npm test`, `npm run check` and `npm run lint` before pushing, plus `npm run build` when bundling or deployment can be affected.

## Writing style

Applies to docs, UI copy, comments, commit messages and PR text.

- No em dashes.
- Do not claim something is tested, secure, fast or complete unless it has been shown.
- Professional but not stuffy. Say each fact once per page. Never invent facts, numbers or links.

## Code style

- Do not over-comment. Use Iconify icons, not emojis.
- In TypeScript, use real types, never `any`.
- Prefer small changes that fit existing conventions. No unrelated cleanup.
- Avoid new dependencies without a clear benefit.

## Testing

- Vitest, in `tests/`.
- Add a few focused tests for important behavior, including failure paths and input boundaries. Avoid tests that mirror implementation details.
